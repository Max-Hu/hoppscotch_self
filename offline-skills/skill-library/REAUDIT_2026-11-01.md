# 离线能力复审：第二版

结论：第一版确有遗漏，不能认定已经清理干净。本次修正后，40 个保留技能入口及所列适配路径通过扩展静态审查和 14 项 Windows 本地测试。此结论不等于删除了所有依赖内部的网络代码，也不等于对所有进程做了零外联认证。本次没有联网下载或查询。

扫描器对旧漏检案例有专门回归测试。动态构造的请求、任意模型行为和所有依赖分支不能靠静态扫描完全证明；零告警不是零外联证明。未做系统抓包、原生 CLI 的系统调用追踪或 Linux 实机测试。

## 仍保留什么

1. 来源区 `upstream/`、`archives/` 和来源 ZIP：完整原件，故意保留联网内容供溯源，不是离线执行入口。
2. `tools/fetch_*.py`：仅来源包内的在线准备工具；运行包不包含。需要用户另行明确授权更新时才用。
3. OpenSpec 原生二进制、Playwright 驱动和通用依赖：内部仍含安装、下载或网络实现。没有篡改发布二进制、删除其所有网络代码或编译零网络版本。OpenSpec 由白名单入口及关闭遥测/版本检查的环境变量限制；浏览器测试由 Python/socket 和页面 context guard 限制。
4. 惰性的文献 URL、许可证和格式标识：仅作来源，不自动获取。项目生成的页面必须使用本地资源。
5. 宿主模型本身的推理连接不在本库控制范围；技能文件离线不意味着当前 Codex 服务已经能在断网机器上推理。

若要求“任意工具、进程都绝不外联”，需要在封闭环境对实际运行栈做系统级隔离和验证。本库现有脚本不是系统防火墙，不能约束所有原生进程或人为绕过入口的命令。

## 使用哪一版

使用 `artifacts/skills-offline-runtime-2026-11-01-r2.zip` 和 `SHA256SUMS-r2`。无 r2 的第一版 ZIP 保留为历史，不应继续用于部署；两版不要叠加解压，否则旧的 Playwright 目录会残留。应解压到空目录，再按 README 合并项目规则。来源包也有对应 r2 版。
